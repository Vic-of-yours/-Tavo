## 0. 怎么使用这份包

1. 先看本登记册，只处理“待校准决策”，不要先改代码。
2. 每个 `CAL-*` 项只能记录为 `accepted / revised / rejected / deferred` 之一，并补充理由。
3. 被修改的决策必须同步更新总蓝图、机器架构 JSON、172 行迁移账和相关验收门。
4. 所有 P0 项确认后才进入 B1；占位模块、接口声明和 UI 外壳都不计实现完成。

本包中的“冻结”表示审计阶段形成的施工候选基线，不表示用户已经最终确认。若本登记册与旧文档中的“冻结”措辞冲突，以本登记册的“待校准”状态为准。

## 2. 校准状态词

| 状态 | 含义 |
|---|---|
| `verified-fact` | 已由来源或测试证明，不是设计完成度。 |
| `candidate` | 当前蓝图建议，等待用户确认或修改。 |
| `open` | 信息不足，尚无唯一方案。 |
| `accepted` | 用户已明确接受，可作为后续阶段合同。 |
| `revised` | 用户接受了修改后的方案，必须同步所有账本。 |
| `retired-verified` | 仅限已证明空项或明确越权/破限内容。 |
