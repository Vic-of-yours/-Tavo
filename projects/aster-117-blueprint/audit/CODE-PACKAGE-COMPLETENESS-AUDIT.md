# Code r002 完整性与去重审计

审计日期：2026-08-21  
结论：r001 包内自洽，但不是最新工作区全量；r002 重建后才可称为“清理后当前树完整”。这里的完整不等于把所有历史、vendor、生成物和参考附件原字节塞入最新包。

## 1. 对用户问题的直接结论

旧 `Code r001` 没有把已选中的独有文件误判成重复后删除：71 个 payload 全部与当时工作树逐字节一致，重复内容为 0，构建器遇到重复会失败而不是保留其一。但 r001 生成后新增了 4 个校准文件，而且最初筛选阶段没有逐文件闭合一批独有设计合同、复现工具和依赖锁。因此，不能再把 r001 称为“所有独有现行文件均在包内”。

r002 的修正是：

1. 清理后当前树的每个文件只按根目录进入 Code 或 Assets，不使用“发现重复后任选一份”的打包逻辑。
2. 任何当前树精确重复会让构建立即失败。
3. 每个源输入文件表示进入 `manifests/full-file-disposition.json`；未知处置为 0。
4. 仍有效但此前遗漏的机器合同、素材生产规格、依赖锁、合同快照导出器和统一素材验证入口已进入当前树。
5. 含旧立绘、旧路径或旧部署声明的文档不原样恢复；其有效责任由空人物槽的 r002 设计合同、catalog 和放行矩阵接替。

## 5. 素材没有因重命名丢失

r001 的 94 个视觉文件哈希集合与 r002 的 94 个视觉文件哈希集合完全相等；0 缺失、0 改写、0 新增。新 catalog 恰好有 94 行，路径、legacyPath、storedName、assetId 和 semanticKey 各自唯一。78 个 SVG 和 16 个栅格全通过格式/尺寸校验；人物栅格为 0。

SVG sprite 与独立图标共享几何、两个场景是其他场景的裁切派生，但都不是相同字节；它们有不同加载或内容用途，暂按蓝图校准项保留，不以“相似”冒充精确重复而擅删。

## 6. 尚不能扩张的结论

- r002 能证明当前清理树可由双包恢复，不能证明四个原始附件的全部字节都已保存在 Git。
- Projects 原包超过 GitHub 普通单文件 100 MiB；只有哈希或逐文件处置账不等于可恢复历史。
- Assets r002 是分类后的可审计源包，不是可直接安装的 `aster.mod/v1`。
- 86 模块仍是待用户校准候选，`implementedVerified=0`；真实 Playwright/Tavo 门未执行前保持 PENDING。
